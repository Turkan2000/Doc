Vahid Reyestr və Məlumat Portalı - Proqram Təminatı Tələblərinin Spesifikasiyası (SRS)

Bu sənəd Vahid Reyestr və Məlumat Portalının hazırlanması və inkişafı üçün tələb olunan funksional və texniki tələbləri vahid şəkildə təsvir edir. Sənəd sistemin əsas məqsədini, biznes proseslərini, istifadəçi ssenarilərini və məlumatların əldə edilməsi, emalı, saxlanılması və təqdim olunması ilə bağlı yanaşmanı müəyyənləşdirir.

Sənəd çərçivəsində DVX və ƏMAS ilə inteqrasiya prosesləri, ilkin məlumatların yüklənməsi və sonrakı məlumat sinxronizasiyası, API servisləri və onların request/response strukturları, error handling və validation qaydaları əhatə olunur. Həmçinin məlumat bazasının strukturu, cədvəllər arasındakı əlaqələr və məlumatların portal daxilində axtarılması və filtrlənməsi üçün nəzərdə tutulan funksionallıqlar təsvir edilir.

Bundan əlavə, sənəddə əsas Use Case-lər, workflow-lar, input validation qaydaları və UI mockuplar təqdim olunur. Bu bölmələr sistemin həm biznes, həm də texniki tərəfinin vahid şəkildə başa düşülməsini təmin edir.

İlkin məlumatların yüklənməsi - DUMP

Məlumatların DVX-dən əldə edilməsi əvvəlcədən təqdim olunan tam məlumat bazası və sonrakı yenilənmələr əsasında həyata keçirilir. İlkin mərhələdə Dövlət Vergi Xidməti (DVX) tələb olunan məlumatları əhatə edən tam məlumat bazasını DUMP şəklində Vahid Reyestr və Məlumat Portalına təqdim edir. DUMP yükləndikdən sonra portalın lokal məlumat bazası formalaşır və gündəlik əməliyyatlar bu lokal baza üzərindən həyata keçirilir.

DUMP REST API çağırışı deyil və ilkin mərhələdə bir dəfə təqdim olunur. Məlumatlar razılaşdırılmış formatda (məsələn: XML, CSV, JSON, Parquet və ya SQL Dump faylı şəklində) ötürülə bilər.

DUMP-da hər bir qeyd Service 02 vasitəsilə əldə edilən məlumatlarla uyğun olan tələb olunan 15 sahəni ehtiva etməlidir. Bu uyğunluq məlumatların lokal bazaya düzgün yüklənməsi və sonrakı yeniləmələrin düzgün tətbiq olunması üçün vacibdir.

İlkin məlumatların formalaşdırılması və ƏMAS sinxronizasiyası

ƏMAS üzrə məlumatların əldə edilməsi və lokal bazanın yenilənməsi aşağıdakı ardıcıllıqla həyata keçirilir:

  1. İlkin məlumatların hazırlanması: DVX-dən əldə edilmiş DUMP bazaya yüklənir və fiziki şəxslərin FİN kodları müəyyən edilir.
  2. ƏMAS məlumatlarının ilkin yüklənməsi: ƏMAS tərəfindən FİN kodlarına uyğun əmək müqaviləsi nömrəsi, müqavilə statusu və iş yeri məlumatları (CSV, XML və s.) formatda təqdim edilir. Bu məlumatlar FİN kodları ilə əlaqələndirilərək lokal bazaya əlavə olunur. Müqaviləsi olmayan şəxslər üçün muqavileNo və muqavileStatus null, isYeri isə "İşləmir" olaraq qeyd edilir.
  3. Dəyişikliklərin müəyyən edilməsi - Service 01: Müəyyən edilmiş tarix aralığı üzrə Service 01 çağırılır və həmin dövrdə dəyişmiş əmək müqavilələrinin köhnə müqavilə nömrələri əldə edilir.
  4. Cari məlumatların əldə edilməsi - Service 02: Əldə edilmiş köhnə müqavilə nömrələri Service 02-yə göndərilir. Servis həmin müqaviləyə uyğun FİN kodu, yeni müqavilə nömrəsi, status və iş yeri məlumatlarını qaytarır.
  5. Bazanın yenilənməsi: FİN kodu əsasında müvafiq şəxs müəyyən edilir və əmək müqaviləsi məlumatları lokal bazada yenilənir. Beləliklə, məsələn, MQ-001 köhnə müqaviləsi MQ-025 yeni müqaviləsi ilə əvəz olunur.

Use Case Spesifikasiyası - Vahid Reyestr və Məlumat Portalı

Use Case ID UC-001
Use Case Name Məlumatların Axtarışı və Reyestri
Actor Portal İstifadəçisi
Preconditions
  • 1. İstifadəçi internet brauzeri vasitəsilə portala daxil olub.
  • 2. Verilənlər bazası və axtarış sistemi işlək vəziyyətdədir.
Main Flow
  1. İstifadəçi Əsas Səhifədə (Qarşılama ekranında) "Qabaqcıl Axtarış və Reyestr" modulunda "Daxil ol" düyməsini seçir.
  2. Sistem "Məlumatların Axtarışı və Reyestri" ekranına keçid edir.
  3. İstifadəçi lazım olan filtrləri tətbiq edir:
    • Ad, soyad, ata adı / Şirkət adı (yazarkən interaktiv avtotamamlama / autocomplete təklif siyahısı açılır)
    • Şəxs növü - Hamısı / Fiziki şəxs / Hüquqi şəxs
    • Hüquqi şəxsin təşkilati-hüquqi forması - Hamısı / MMC / ASC / QSC
    • Tarix aralığı - Başlanğıc tarixi və Bitmə tarixi
    • Əmlak növü - Hamısı / Daşınar / Daşınmaz
    • VÖEN (daxil edərkən interaktiv VÖEN avtotamamlama siyahısı açılır)
  4. İstifadəçi "Axtar" düyməsini seçir.
  5. Sistem daxil edilmiş filter parametrlərinə uyğun məlumatları bazadan sorğulayır və əldə edir.
  6. Sistem axtarış nəticələrini səhifələmə (pagination - hər səhifədə maksimum 30 qeyd) tətbiq olunmaqla cədvəl şəklində göstərir (№, Ad, Soyad / Şirkət Adı, Şəxs Növü, Təşkilati Forma, VÖEN, Əmlak Növü, Qeydiyyat Tarixi, Əməliyyat).
  7. İstifadəçi axtarış nəticələri cədvəlində müvafiq sətrin qarşısındakı "Bax" düyməsini klikləyir.
  8. Sistem "Qeydiyyat Detalları" adlı modal pəncərəni açır və seçilmiş qeydə aid məlumatları göstərir:
    • Ad / Şirkət
    • Şəxs Növü
    • Təşkilati Forma
    • VÖEN
    • Əmlak Növü
    • Qeydiyyat Tarixi
  9. İstifadəçi modal pəncərədə "Çıxarış Yüklə" düyməsini sıxaraq rəsmi sənədi əldə edir və ya "Bağla" düyməsi ilə pəncərəni bağlayır.
Alternative Flow
AF-1 - Əsas Səhifəyə qayıdış naviqasiyası

İstifadəçi naviqasiya panelində "Əsas Səhifə" düyməsinə və ya portalın loqotipinə kliklədikdə sistem axtarış ekranından ilkin Qarşılama səhifəsinə qayıdır, "Əsas Səhifə" düyməsi gizlənir və ümumi statistik modullar göstərilir.

AF-2 - Cəld tarixlərin seçilməsi

İstifadəçi təqvimləri əllə doldurmaq əvəzinə "Bugün", "Son 30 gün", "Bu il" və ya "Hamısı" cəld seçim düymələrindən istifadə edərək tarix aralığını avtomatik təyin edir və axtarışı icra edir.

AF-3 - Avtotamamlama (Autocomplete) vasitəsilə seçim

İstifadəçi Ad və ya VÖEN sahəsinə yazarkən açılan təklif siyahısından istədiyi şəxsi/şirkəti klikləyərək seçir və axtarış parametrlərini avtomatik tamamlayır.

AF-4 - Filterlərin təmizlənməsi

İstifadəçi "Filteri təmizlə" düyməsini seçdikdə bütün daxil edilmiş parametrlər və aktiv filter etiketləri sıfırlanır, axtarış xanaları təmizlənir.

AF-5 - Səhifələmə (Pagination) üzrə naviqasiya

Axtarış nəticələri 30-dan çox olduqda istifadəçi cədvəlin altında yerləşən "Əvvəlki", "Növbəti" və ya səhifə nömrələri düymələrindən istifadə edərək səhifələr arasında rahat keçid edir.

AF-6 - Nəticələrin ixracı və çapı

İstifadəçi axtarış nəticəsində əldə edilmiş siyahını "CSV İxrac" düyməsi ilə .csv faylı kimi endirir və ya "Çap et" düyməsi ilə sənədi birbaşa çap edir.
Exception Flow
EF-1 - Məlumat tapılmadı

Seçilmiş filter parametrlərinə uyğun heç bir qeydiyyat aşkar edilmədikdə sistem cədvəli gizlədir, "Məlumat tapılmadı" xəbərdarlıq blokunu və "Filtrləri sıfırla" düyməsini göstərir.

EF-2 - Server/Baza xətası

Verilənlər bazasına və ya sistem komponentlərinə qoşulmaq mümkün olmadıqda sistem istifadəçiyə "Məlumat bazası ilə əlaqə qurulmadı. Zəhmət olmasa bir az sonra yenidən cəhd edin." xəta mesajını göstərir.

EF-3 - Yanlış filter məlumatı

İstifadəçi sahələrə yanlış formatda məlumat daxil etdikdə sistem axtarışın icrasına icazə vermir və müvafiq xəta mesajlarını göstərir:

  • VÖEN yanlış daxil edildikdə: "VÖEN 10 rəqəmdən ibarət olmalıdır."
  • Tarix aralığı yanlış daxil edildikdə: "Başlanğıc tarixi bitmə tarixindən böyük ola bilməz."
Postconditions
  • 1. İstifadəçiyə seçilmiş kriteriyalara uyğun fiziki və ya hüquqi şəxslərin mövcud reyestr və əmlak məlumatları təqdim olunur.
  • 2. Seçilmiş qeydin "Qeydiyyat Detalları" məlumat kartı görüntülənir və çıxarış generasiya edilə bilər.
  • 3. Məlumatlar yalnız oxuma məqsədilə təqdim olunur və bu Use Case çərçivəsində baza məlumatlarında dəyişiklik edilmir.
